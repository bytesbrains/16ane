# Changelog

User-visible changes to this repository. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [Semantic Versioning](https://semver.org/) (see *Versions and releases* in [CONTRIBUTING.md](CONTRIBUTING.md)).

Nothing has been released yet: no version is tagged, and no package is published to npm or PyPI. Everything below is on `main` at version `0.1.0`. `tANE` is a free testnet token with no monetary value, and nothing here is deployed to a public network.

## [Unreleased]

### Added
- Planning specification: requirements, protocol docs, threat model, ADR-0001 to ADR-0015, traceability, proposed issues and launch-readiness gates.
- Solidity contracts in `src/`: `AneTestToken` (`tANE`), `AneAgentVault`, `AneVaultFactory`, `AneFaucet`, `AneRegistry` and `AneServiceDirectory`, with Foundry unit, fuzz and invariant tests and a Base Sepolia deployment script that CI runs as a dry run.
- TypeScript SDK `@16ane/sdk` (`packages/sdk-ts`, with its own README) and Python SDK `16ane-sdk` (`packages/sdk-py`, import `ane_sdk`).
- `ane` CLI (`packages/cli`).
- Reference sandbox server with an x402 payment flow, faucet and demo endpoints (`services/sandbox-server`). It runs locally and in the E2E suite only.
- E2E scenarios S1 to S6 and threat-model checks T1 to T10 (`e2e/`).
- `16ane.com` overview page served from Cloudflare Workers (`web/`, ADR-0015).
- CI: Foundry, TypeScript type-check, SDK, CLI, server and E2E tests; Python lint and packaging; Slither (medium and above); committed-file hygiene; gitleaks secret scan.
- **Sandbox contracts deployed to Base Sepolia** (2026-10-20, from `e43ccc8`): registry `0x01d5daB670DE5868305eB862721ebE62772C3Df3`; all addresses in `networks/sandbox-sepolia.json`. All six contracts, including the `AneAgentVault` implementation, are source-verified on Basescan.
- Relayer daily gas budget (#76, ADR-0006): the server counts the full fee of every transaction its relayer pays for (L2 gas plus Base's L1 data fee) per UTC day, in its persistent store, holding back gas for each send before it goes out so concurrent requests can't overspend; over `ANE_RELAYER_GAS_BUDGET_WEI` (default 0.05 ETH) it answers `503 ANE-E-1006` with `Retry-After` and a self-serve hint. `/healthz` reports budget, spend, holds, relayer balance and `lowBalance` (below one day's budget). The SDK gains `AneClientOptions.sendHooks` (before/after/failed, once per transaction, with the fee) and `castSend` moves to its own module.
- Sandbox server state persists across restarts (#75): a `KeyValueStore` interface in the SDK (memory by default) used by `AnePaymentVerifier` (idempotency records, consumed payment proofs, receipts) and `TrialQuotaTracker`; the server adds a SQLite store (Node's built-in `node:sqlite`, no npm dependency) for those plus faucet cooldowns, claims and the service directory, selected by `ANE_STATE_PATH` (`/data/sandbox.sqlite` in the image). The sponsored-trial disclosure now states the configured quotas instead of fixed numbers.
- Sandbox server runs on its own and in Docker (ADR-0016, #73, #74): start command configured from `ANE_*` environment variables, configurable listen address, `GET /healthz`, graceful shutdown; a portable multi-arch image (Node 24, checksum-pinned Foundry `cast`, non-root, no secrets) with an end-to-end CI check (`scripts/docker-smoke.sh`); self-hosting guide `docs/operations/SELF_HOSTING.md`.
- `POST /v1/relay` (#77): the reference server relays owner-signed actions and pays their gas: `transfer` (EIP-3009), `createVault`, `setPolicy` (`setPolicyWithSig`) and `revoke` (`revokeWithSig`). Shape, deadline, signer (recovered locally), target (the tANE token, the factory, or a registered vault), the gas-price ceiling and a simulation from the relayer's address are checked before anything is sent; refusals are `400 ANE-E-1201`, `403 ANE-E-1202`, `409 ANE-E-1203`, `422 ANE-E-1204`, `503 ANE-E-1205`. The relayer's gas-price ceiling (`ANE_RELAYER_MAX_FEE_WEI`, ADR-0006) now applies to faucet claims and relayed actions. The SDK gains calldata builders (checked against `cast calldata`) and `AneClient.simulateCall`. E2E: an owner and agent with no ETH do the whole journey through the server, and a replayed signature is refused without gas.
- Owner-signed actions for a relayer to submit (#77, SDK): `OwnerWallet.signTransfer` (EIP-3009; also how a vault is funded, since `fundWithPermit` can't be relayed), `signPolicy` (`setPolicyWithSig`), `signRevoke` (`revokeWithSig`) and `signVaultCreation` (checked by a relay server; the factory needs no signature), plus `relayTransfer`, `relaySetPolicy`, `relayRevoke` and `relayCreateVault`. An e2e journey runs claim, vault creation, funding, delegation, an x402 payment and revocation for an owner and agent that never hold ETH. Contract tests cover `setPolicyWithSig`, `revokeWithSig` and relayed EIP-3009 funding, which had none.
- Read-after-write consistency on public RPCs (#67): for 60 s after its last confirmed transaction (`readFloorWindowMs`), `AneClient` reads state at a block no older than that transaction's, waiting while the node answering is behind and retrying a node that doesn't have the block yet (`block not found`, `header not found`). It fails clearly if the node never catches up, instead of returning old state. `observeBlock(n)` applies the same to a write made elsewhere; `verifySettlementOnChain` asks again for a receipt a lagging node doesn't have yet; `getEthBalance` added.
- Hosted API checks (#78): `scripts/smoke-api.ts`, a keyless end-to-end smoke test for a hosted sandbox API (health, a `401` without a proof, a signed gasless claim landing on-chain, cooldown, `402` quote, manifest signature), and `scripts/api-health.ts` with the scheduled `API monitor` workflow, which opens one `api-alert` issue when `/healthz` shows the RPC down, a low relayer, a used-up gas budget or the wrong registry, and closes it on recovery. Off until the `SANDBOX_API_URL` repository variable is set. Runbook in `docs/operations/OPERATIONS.md`.
- Faucet claim proofs (#79, ADR-0006): `POST /v1/faucet/claims` needs an `authorization` signed by the recipient (the EIP-712 `FaucetClaim` that `AneFaucet.relayedClaim` checks; `AneClient.signFaucetClaim` in the SDK, `ane wallet fund --test` with `ANE_OWNER_PRIVATE_KEY` in the CLI) or a Cloudflare Turnstile token (`ANE_TURNSTILE_SECRET_KEY`, `ANE_TURNSTILE_HOSTNAME`). Signer, deadline, cooldown and on-chain nonce are checked before the relayer sends, so refused claims (`401 ANE-E-1007`, `403 ANE-E-1008`, `409 ANE-E-1009` for a concurrent duplicate) cost no gas. Claims without a proof need `ANE_FAUCET_OPEN_CLAIMS=true`. **Breaking** for callers that sent only `{"recipient"}`.
- Fly.io deployment config for the sandbox API (#78): `fly.toml` (org `bytesbrains`, region `sin`, one always-on machine with a `/data` volume, `/healthz` checks) and `docs/operations/DEPLOY_API.md` (keys generated straight into Fly secrets, DNS-only `api.16ane.com`). The server can take the client address from a header the platform proxy sets (`ANE_CLIENT_IP_HEADER`, `fly-client-ip` on Fly.io), so per-client trial quotas see real clients, not the proxy.
- Base Sepolia deployment runbook (`docs/operations/DEPLOY_SANDBOX.md`) and an end-to-end smoke test for a deployed sandbox (`scripts/smoke-sandbox.ts`, also run by the E2E suite). `DeploySandbox.s.sol` can sign from an encrypted Foundry keystore (`--account`), so the deployer key need not be in the environment.
- Git hooks: gitleaks and `forge fmt` before commit; gitleaks, committed-file hygiene and `forge test` before push.
- Brand images in use: the README banner (`assets/16ane_social_preview.png`), link previews for 16ane.com (Open Graph and X/Twitter tags with `web/og-image.png`), the logo on the Python SDK's README, and homepage, source and issue links in the Python and TypeScript package metadata.
- Community files: `LICENSE` (MIT), `SECURITY.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1), issue and PR templates, `CODEOWNERS`.
- Tagged API releases (#78): pushing a `sandbox-api-v*` tag on `main` runs `.github/workflows/release-api.yml`, which checks the tag is on `main`, builds the Dockerfile on Fly, deploys `16ane-sandbox-api`, smoke-tests the live app (`scripts/smoke-api.ts`) and records a GitHub release. First-time setup (app, volume, keys, `FLY_API_TOKEN` secret) stays in `docs/operations/DEPLOY_API.md`.

### Changed
- Hosted API's day-one relayer gas budget is 0.001 Base Sepolia ETH per UTC day (`fly.toml`), sized to the relayer's starting funds so the deploy smoke gate's funding check passes; raise it as funding grows. The code default stays 0.05 ETH.
- E2E scenarios S1–S6 live in `e2e/scenarios/` (#65); `e2e/run-scenarios.ts` only boots the shared stack and runs them in order. No behaviour change.
- Faucet and relayer limits sized for agent-speed use (#61): faucet defaults 16,000 tANE per claim, 1 hour cooldown per recipient, 160 M tANE per day (were 1,600 / 24 h / 1.6 M); ADR-0006, ADR-0008 and ADR-0010 amended so the payment path carries no protocol rate limits or count caps, and operator-paid resources are limited by cost only.
- tANE described as the shared sandbox currency across platforms: providers can price sandbox, demo and introductory/offer-credit tiers in tANE, and agents pay every participating provider from one balance (README, VISION, TOKENOMICS, SANDBOX_AND_CREDITS, 16ane.com). No change to tANE's no-value status.

### Fixed
- Hosted API no longer OOMs under relay load: Fly's kernel killed the uncapped Node process (~150MB RSS on the 256MB box). The image now caps V8 at 192MB (`NODE_OPTIONS=--max-old-space-size=192`, so the collector runs before the kernel acts) and the machine is 512MB (`fly.toml`).
- SDK transactions no longer fail on public load-balanced RPCs right after a previous transaction confirms: `sendContractTx` retries "nonce too low" and "replacement transaction underpriced", which mean the transaction was rejected and never broadcast. The deployment smoke test waits for its own writes to become visible before reading them.

### Security
- SDK: private keys no longer appear in `cast`'s process arguments (#67). Each `sendContractTx` writes the key as a temporary encrypted V3 keystore (scrypt, aes-128-ctr) with a random password in a private temporary directory, passes it to `cast` as `ETH_KEYSTORE` / `ETH_PASSWORD`, and deletes it afterwards. The CLI, which reads keys from `ANE_*_PRIVATE_KEY`, gets this through the SDK.
- SDK: `AnePaymentVerifier` reserves a payment proof synchronously before verifying or settling it, so two concurrent requests with the same proof can't both be served. The direct-`txHash` path, whose verification is read-only, let one on-chain payment buy a service twice.
- SDK: contract arguments passed to `sendContractTx` can no longer be read by `cast` as options. A value such as `--value=1ether` used to make `cast` send ETH from the signer; `--` now ends the option list before the target and its arguments.
- Sandbox server: request bodies capped at 1 MiB, trial quota keyed on the connection address, and `X-Forwarded-For` trusted only with `trustProxy` (#31).
- Sandbox server: error responses no longer echo internal error text, which could include the RPC URL and the `cast send` command line (#52). Failures that may carry internal detail return a fixed message and an `errorId`; the detail is logged server-side with URLs redacted. A failed faucet claim is now `502` (was `429`), and a malformed JSON body is `400 ANE-E-4000` (was `500`).
