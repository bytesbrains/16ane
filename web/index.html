Open Agent Economy · sandbox in development

Give an agent a budget. Let it spend, earn, and return what’s left.

16ane is open-source software for AI agents that pay each other for services. An owner funds an isolated wallet, sets a fixed budget, and the agent buys within it. The limit is enforced by a smart contract, not by instructions in a prompt.

TEST TOKENS (tANE) - NO CASH VALUE

  • tANE is a free, simulated test token. It is not money, cannot be redeemed, and does not convert into anything.
  • There is no token sale, no presale and no tradable 16ane token. Anyone offering to sell you one is not us.
  • When contracts are deployed, their addresses will be published only in the GitHub repository and on this page.

How it works

  1. Fund

    An owner puts test tokens in a vault that belongs to one agent, separate from the owner’s own wallet.

  2. Limit

    The owner sets a fixed budget. The vault contract refuses any payment that would go over it.

  3. Spend and earn

    The agent pays for APIs and services over HTTP using x402, and can sell its own. Under a fixed budget, what it earns never raises what it may spend.

  4. Return

    The owner can revoke the agent and withdraw what is left. Every payment has a receipt anyone can check on-chain.

One test currency for every sandbox

Today every AI platform runs its own sandbox, demo tier or introductory credits, each with its own sign-up, keys and rules. tANE is meant to be one shared test currency for all of them. A provider that offers a sandbox, demo or introductory tier can price it in tANE, and any agent can pay from the same balance, with no separate account or card for each provider.

Balances work across the whole network: tANE an agent gets from the faucet, or receives for serving other agents, can be spent at any participating provider. Providers take part voluntarily, set their own prices and limits, and pay for any real compute they sponsor. tANE stays a test token: it has no cash value, cannot be bought or sold, and never turns into money or ANE.

Where it stands

Works today locally and in CI

  • Contracts: test token, agent vault, faucet and registry, with fuzz and invariant tests
  • x402 payments with idempotency and verifiable receipts
  • TypeScript and Python SDKs and the ane CLI, in the repository
  • End-to-end scenarios against a throwaway local chain

Not live yet

  • Contracts on the Base Sepolia testnet
  • A public faucet and demo API
  • Providers accepting tANE for their sandbox, demo or trial tiers
  • Developer docs and an owner dashboard
  • SDK packages on npm or PyPI

Progress is tracked gate by gate in the launch-readiness report.

Why “16ane”?

Sixteen annas once made a rupee. The name is a nod to that history, not a price: tANE is not worth any amount of rupees, or of anything else.

The same ratio is the long-term proposal for a separate token, ANE, on a public mainnet: 16 ANE = ₹1, with rupee reserves held by a licensed institution. That is a proposal, not a promise. It can only happen if Indian law and regulators allow it, and none of it exists today (tokenomics). tANE will never turn into ANE.
